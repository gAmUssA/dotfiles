# Local model benchmark records

One file per machine, generated by `../bench-record.sh`. Compare machines by
diffing the files.

## Reproducing on another Mac

```bash
git clone https://github.com/gAmUssA/dotfiles ~/projects/dotfiles
cd ~/projects/dotfiles
brew bundle                 # needs openjdk, kotlin, and Xcode's swiftc
./ollama-restore.sh         # pulls the exact model set (ollama must be running)
./bench-record.sh qwen3-coder:30b qwen3.6:27b devstral:24b qwen2.5-coder:7b
```

That writes `bench-results/<chip>-<ram>gb.md`. Commit it and the machines are
comparable.

Run `./bench-record.sh` with **no arguments** to re-generate a record from the
last `bench-out/headtohead.log` without re-running inference.

## What makes the comparison valid

The bench grades by **compiling and running** each model's output — a `✅` means
the program actually ran, not that it looked right. That makes it a much better
signal than an eyeballed diff, but it also means several non-CPU things can move
the result. Each record pins them:

| pinned | why it matters |
|---|---|
| **model digest** | Tags get re-uploaded. Two machines both on `gemma4:26b` can hold different weights. The digest is the only honest identity — **check it matches before comparing.** |
| **javac / kotlinc / swiftc** | A newer Swift release can flip a `✅` to a `❌` with the model unchanged. Without this you would blame the chip. |
| **ollama version** | Inference-engine changes move tok/s on their own. |
| **RAM** | Decides whether a model stays on the GPU or spills — the single biggest tok/s cliff. |

If the digests differ between two records, you are comparing two different
models, not two machines. Fix that first.

## What this bench does NOT measure

**One-shot generation only** — three prompts, no tool calls, no iteration, no
multi-file editing.

That distinction matters for picking models. Independent evaluations of Gemma 4
26B found it scoring near frontier models on *one-shot* coding while
**underperforming on agentic coding and tool use** — plausibly overfit to common
agentic harnesses. A model can therefore top this table and still be the wrong
choice for the OpenCode/Pi driver, which is a tool-calling loop.

Read this table for the tmux popup slot (`prefix + a`, one-shot Q&A). Do not
read it as an agentic ranking.

## Tasks

| id | tests |
|---|---|
| `java` | Java 21 sealed interface + records + pattern-matching switch |
| `kotlin` | kotlinx.coroutines `async`/`awaitAll` over a sealed result type |
| `swift` | Swift 6 `actor` + `Codable` + `@main`, must be clean under strict concurrency |

Prompts live in `../ollama-code-bench-one.sh`. All run at `temperature 0.1`,
`num_predict 2048`, `think: false`.
